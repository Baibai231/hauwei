# ScholarFlow 南开平台演示

## 入口

[打开 ScholarFlow 科研助手](https://coze.nankai.edu.cn/product/llm/chat/db42qo54shhbpg8vnl40)。当前发布版本为 v1.0.0。

需要先完成南开统一身份认证。应用配置虽允许匿名访问，实测站点网关仍要求登录；不要把链接描述为校外免登录公开服务。

## 两步演示

1. 输入：“我想研究 RAG 是否能改善代码安全漏洞检测。请先检索两篇相关论文，基于实际摘要做证据表，区分作者报告与待验证假设，然后给我下一步行动。找不到就如实说。”
2. 接着输入：“把当前研究整理成对话内项目卡，再给一个包含基线、F1、误报、检索库排除测试样本、预算和失败条件的最小实验方案。没有实际数据的部分标为建议。”

演示重点是按研究问题选择真实检索、检查来源与摘要、区分直接证据和方法启发，并根据证据推进下一步。检索结果随外部服务变化，不能保证固定篇数、固定标题或固定响应时长；空结果与失败应如实说明。

上线检查已遇到 arXiv HTTP 429 限流。发生该错误时停止重复检索，可改为下面的“已检索材料回放”；必须向观众说明它不是本次实时检索成功。

## 已检索材料回放（限流时）

下面的标题、链接与研究对象来自 2026-10-08 23:59 的成功 arXiv 工具返回记录。中文材料是摘要事实的转述，不是新检索或全文分析。

输入：“不调用检索工具。这是我提供的既有材料：EVOR: Evolving Retrieval for Code Generation，链接 https://arxiv.org/pdf/2402.12317v2。摘要介绍检索增强代码生成，提出查询和多来源知识库同步演化的 EVOR 方法；研究对象是代码生成，不是安全漏洞检测。我想借鉴其思路研究漏洞检测。请基于这些材料做证据表，把直接证据和方法启发区分开，再给待验证假设与最小实验建议。未知信息写未提供，不宣称本次实时检索成功。”

这个模式可演示资料分析、证据边界和实验规划，不可替代实时工具稳定性验收。

## 不应宣称的功能

- 项目已自动保存到独立网页工作台。
- 已自动读完未提供的论文全文。
- 已执行实验、复现论文数字或完成统计显著性检验。
- 已部署失败的原生 ResearchEvidenceAudit 工作流。
- 已具备跨对话项目持久化、后台定时提醒或外部 OpenAlex 接口连接。

平台编辑入口和聊天访问入口不同；提交比赛应使用聊天链接，并确认评审可完成平台登录。比赛其他材料仍按官方要求另行准备。
